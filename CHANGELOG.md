# Changelog

## Unreleased

### Breaking changes

- `RowState` is removed from `BaseTypeLibrary`, together with `SetForInsert`, `SetForUpdate` and `SetForDeletion`.
  Karkas no longer tracks whether an entity was added, changed or deleted.
- `BatchInsertUpdateDelete` and `InsertUpdateDeleteAccordingToState` are removed from `BaseDal` and `BaseBs`, as they
  chose the operation from `RowState`. Call `Insert`, `Update` or `Delete` yourself:

  ```csharp
  foreach (Album album in albums)
  {
      albumBs.Update(album);   // was albumBs.BatchInsertUpdateDelete(albums)
  }
  ```

**Regenerate your code.** Property setters generated by earlier versions set `RowState`, so they do not compile
against this version of `Karkas.Data*`. The new generator writes plain setters. Hand-written partial classes keep
working unless they use `RowState` or the removed methods.

## 2.2.0 (2026-11-21)

### Breaking changes

- The obsolete `BringOneValue` and `GetListOfDictionary` methods are removed from the `AdoTemplate*` classes
  (`BaseAdoTemplate`). Use `GetOneValue` and `GetRows` instead. They take the same arguments:

  ```csharp
  object count = template.GetOneValue("SELECT COUNT(*) FROM Album");   // was BringOneValue
  var rows = template.GetRows("SELECT * FROM Album");                    // was GetListOfDictionary
  ```

### Fixed

- Generated `QueryBy<PrimaryKey>` methods now pass the key as a parameter. Before, they formatted it into the SQL
  text (`String.Format(" REGION_ID = '{0}'", p)`), so tables with string keys were open to SQL injection, and numeric
  or date keys depended on the current culture (for example `1,5` instead of `1.5` on a Turkish system).
  Regenerate your code to get the fix.
- SQLite tables whose primary key is not auto-increment (for example a `TEXT` key) now compile: `BaseDalSqlite` was
  missing the `DbProviderName` override.

## 2.1.0 (2026-11-21)

### Added

- Multi-tenant SQLite with one database file per tenant. `SqliteTenantConnectionFactory` (in `Karkas.Data.Sqlite`)
  maps a tenant id to its file through a path pattern and returns a connection you pass to the generated classes:

  ```csharp
  var tenants = new SqliteTenantConnectionFactory("tenants/{tenant}.sqlite");
  var albumBs = new AlbumBs(tenants.CreateConnection("acme"));   // or CreateConnection(tenantGuid)
  ```

  - Tenant ids may contain 1-64 letters, digits, `-` and `_`, so Guids in `D` and `N` format work. Anything else
    (for example `../x`) throws `ArgumentException`. Ids are lower-cased, so `ACME` and `acme` are the same tenant.
  - Connections open with `Mode=ReadWrite`: an unknown tenant throws the new `TenantNotFoundException` instead of
    creating an empty database. `TenantExists` and `GetDatabasePath` are available for checks.
  - Transactions stay inside one tenant's file, as `GetDalInstance` shares the Bs connection.
  - Creating tenant databases and applying schema changes to all of them is up to the application.
  - `ITenantConnectionFactory` and `BaseTenantConnectionFactory` (in `Karkas.Data`, namespace `Karkas.Data.Tenancy`)
    are database independent, so SQL Server and Oracle versions can be added later.

  The code generator is unchanged, and code generated by 2.0.0 works as is. Generate from any one tenant's file.
  See [docs/multi-tenant.md](docs/multi-tenant.md).

## 2.0.0 (2026-11-21)

2.0.0 removes the global connection singleton. Generated code now receives its database connection through
its constructor. This is a breaking change: regenerate your code with `karkas-codegen` 2.0.0 and update the
places where you create Bs and Dal classes (see [Migrating from 1.x](#migrating-from-1x)).

**Use the same version for the tool and the packages.** Code generated by `karkas-codegen` 2.x needs
`Karkas.Data*` 2.x, and code generated by 1.x needs `Karkas.Data*` 1.x. Mixing them does not compile.

### Breaking changes

- `ConnectionSingleton` is removed. Connections are no longer registered globally with `AddConnection`.
- Generated Bs classes have a single constructor that takes a `DbConnection`: `new AlbumBs(connection)`.
  The parameterless constructor is gone.
- Generated Dal classes and the `AdoTemplate*` classes get a constructor that takes a `DbConnection`.
  Their parameterless constructor stays (Karkas creates them internally and assigns `Connection` afterwards), but
  using one without a connection now throws `InvalidOperationException` instead of reading a global connection.
- The `DatabaseName` property of Bs and Dal classes is removed. Pass the connection of the database you want instead.
  Hand-written partial classes that override `DatabaseName` must drop the override.
- The `UseMultipleDatabaseNames` configuration option is removed. Existing `karkas-config.json` files that still
  contain it keep working; the value is ignored.
- `karkas-codegen` now exits with code 1 on invalid arguments, unsupported database types, connection failures
  and code generation errors (it used to exit with 0 or crash). Scripts that relied on exit code 0 may need changes.
- SQL Server connection error messages no longer include the connection string (it often contains the password).

### Target frameworks

- `Karkas.Data`, `Karkas.Data.Sqlite`, `Karkas.Data.SqlServer` and `Karkas.Data.Oracle` target
  `net8.0`, `net9.0`, `net10.0` and `net11.0`.
- `karkas-codegen` (`Karkas.CodeGeneration.ConsoleApp`) is built for .NET 10 and also runs on newer runtimes
  (`RollForward=Major`), so it works when only .NET 11 is installed. It needs .NET 10 or later.
- `Microsoft.Data.Sqlite` 11.x supports only .NET 10 and later. `Karkas.Data.Sqlite` depends on 10.x, which supports
  .NET 8 and later. If your .NET 8 or 9 project references `Microsoft.Data.Sqlite` directly, use a 10.x version
  (`dotnet add package Microsoft.Data.Sqlite --version 10.0.15`) or remove the reference; it comes with
  `Karkas.Data.Sqlite`.

### Fixed

- An `AdoTemplate` created with a connection string made a new `DbConnection` on every `Connection` access.
  It now creates one connection and reuses it.
- `karkas-codegen` crashed instead of reporting a failed database connection.
- `ConnectionDatabaseType` in `karkas-config.json` is case-insensitive everywhere. Before, `"sqlserver"` crashed and
  `"SQLITE"` was rejected; only `"sqlite"`, `"SqlServer"` and `"Oracle"` worked.
- WinApp: the "Force Oracle Decimal To Int-Dec" checkbox showed the value of a different option when a
  configuration entry was loaded.

### Security

- Updated dependencies with known vulnerabilities: `Oracle.ManagedDataAccess.Core` 23.7.0 → 23.26.401
  (it pulled in a vulnerable `System.Security.Cryptography.Pkcs` 8.0.0) and `Microsoft.SourceLink.GitHub`
  8.0.0 → 10.0.404 (vulnerable `Microsoft.Build.Tasks.Git` 8.0.0).
- Also updated: `Microsoft.Data.Sqlite` 8.0.8 → 10.0.15 and `Microsoft.Extensions.Logging` 6.0.0 → 10.0.15.

### Migrating from 1.x

1. Update the tool and regenerate. The `*.generated.cs` files are overwritten; your hand-written partial classes
   are kept.

   ```bash
   dotnet tool update --global Karkas.CodeGeneration.ConsoleApp
   karkas-codegen -c <connection name>
   ```

2. Update the packages to the same version:

   ```bash
   dotnet add package Karkas.Data --version 2.0.0
   dotnet add package Karkas.Data.Sqlite --version 2.0.0   # or .SqlServer / .Oracle
   ```

3. Replace the global registration with connections you pass in.

   Before (1.x):

   ```csharp
   DbProviderFactories.RegisterFactory("Microsoft.Data.Sqlite", SqliteFactory.Instance);
   ConnectionSingleton.Instance.AddConnection("Main", "Microsoft.Data.Sqlite", connectionString);

   var albumBs = new AlbumBs();
   var employeeDal = new EmployeeDal();
   ```

   After (2.0):

   ```csharp
   DbProviderFactories.RegisterFactory("Microsoft.Data.Sqlite", SqliteFactory.Instance);
   DbConnection connection = new SqliteConnection(connectionString);
   // or: DbProviderFactoryHelper.CreateConnection("Microsoft.Data.Sqlite", connectionString)

   var albumBs = new AlbumBs(connection);
   var employeeDal = new EmployeeDal(connection);
   ```

   Keep the `RegisterFactory` call: Karkas still uses the provider factory, for example in
   `DbProviderFactoryHelper.CreateConnection` and the `DataTable` helpers.

4. If you used several databases (several `AddConnection` names, `DatabaseName` overrides or
   `UseMultipleDatabaseNames`), create one connection per database and pass the right one to each Bs or Dal.

Transactions work as before: a Bs shares its connection with the Dal classes it uses, including
those from `GetDalInstance`.
